# 特征平台设计说明

## 目标

离线训练与线上服务使用**同一份特征定义**，且同一实体在同一时刻
离线算出的值必须等于线上返回的值。

## 数据流

```
事件流（event_time, user_id, item_id, ...）
        │
        ├──> 离线：Polars 按窗口聚合 ──> Parquet ──> 训练
        │                            └─> JSON 快照 ──> Redis
        │                                                    │
        └──────────────────────────────────────────────> 线上 Go 服务
                                                             │
                                                             ▼
                                                        特征向量
```

## 时间点正确（point-in-time）

训练样本 `(user, t, label)` 的特征必须只用到 `t` 之前的信号。
否则就是标签泄漏：模型学到了"未来信息"，离线 AUC 虚高，线上暴跌。

离线侧目前用 `max(event_time)` 作为统一的 `as_of`，
所有样本共享一个窗口右端。

## 窗口语义

| 项 | 必须显式约定 |
|---|---|
| 右端 | 开区间（`< T`）还是闭区间（`<= T`） |
| 左端 | 开区间（`> T-w`）还是闭区间（`>= T-w`） |
| 时间列 | `event_time` 还是 `ingest_time` |
| 时区 | UTC 还是业务时区 |

任何一个含糊，离线与线上就会漂移。

## 缺失值

三种处理方式，语义完全不同：

| 方式 | 含义 | 适用场景 |
|---|---|---|
| 填 0 | "没有就是 0" | 计数类（订单数） |
| 填 NaN | "不知道" | 连续值（金额、比率） |
| 显式标记 | `has_value: false` | 所有场景的通用做法 |

离线侧填 0，线上侧先记 NaN 再替换为默认值。

## 训练/服务一致性

判定标准是**逐字段相等**，不是"分布相似"。

```
for each sample:
    offline = recompute(sample.features, as_of=sample.label_time)
    online  = service.get(sample.entity_id)
    assert offline == online
```

`featureline/parity.py` 实现了这个对比，`scripts/verify_features.py` 把它变成四项断言。

## 回填

回填 N 天 = 对 N 个历史时点各算一次特征。

三种实现方式，成本差一个数量级：

| 方式 | 复杂度 | 30 天成本 |
|---|---|---|
| 逐日全量重算（当前） | O(N × 全量) | 6 小时 |
| 日粒度预聚合 | O(N × 分片) | ~10 分钟 |
| 滚动状态增量 | O(增量事件) | ~1 分钟 |

## 跨语言契约

Go 与 Python 共享的只有"特征名 + 窗口长度 + 默认值"这份定义。
当前是两份手写代码，没有任何自动校验。

时间格式也是一个坑：Go 输出纳秒精度，Python 3.10 只接受微秒。

## 观察点

| 指标 | 位置 | 正常范围 |
|---|---|---|
| 快照新鲜度 | `verify_features.py` V4 | < 24 小时 |
| 窗口内事件数 | V1 | > 0（除非真的无数据） |
| 缺失值语义 | V3 | 无 `NaN -> 0` 的 note |
| 对齐后差异 | V2 | 0 |

## 待决策

1. 窗口右端开闭：统一成左闭右开（主流）还是左闭右闭（业务习惯）。
2. 缺失值：是否引入 `has_value` 布尔列，彻底摆脱 0/NaN 的语义重载。
3. 特征定义的单一来源：YAML 生成两边代码，还是共享一个 IDL。
4. 快照新鲜度：服务层拒绝过期快照，还是降级返回并打点。
